# 가장 긴 팰린드롬 부분 문자열 풀이

## 1. 문제 요약

길이가 `n`인 문자열 `s`에서 연속한 부분 문자열 중 앞뒤가 같은 가장 긴 문자열 하나를 찾는다.

## 2. 핵심 관찰

모든 팰린드롬에는 중심이 있다. 길이가 홀수이면 중심은 문자 하나이고, 길이가 짝수이면 중심은 인접한 두 문자 사이이다. 중심의 좌우 문자가 같은 동안 범위를 확장하면 그 중심을 갖는 가장 긴 팰린드롬을 정확히 얻을 수 있다.

## 3. 알고리즘 선택과 대안 비교

- 모든 부분 문자열을 만들고 각각 뒤집어 확인하면 부분 문자열이 `O(n²)`개이고 확인에도 `O(n)`이 걸려 총 `O(n³)` 시간이 필요하다.
- 동적 계획법은 `O(n²)` 시간에 해결하지만 `O(n²)` 메모리를 사용한다.
- Manacher 알고리즘은 `O(n)` 시간이지만 구현과 증명이 훨씬 복잡하다.
- 중심 확장은 `O(n²)` 시간과 `O(1)` 추가 공간을 사용한다. `n <= 1000`에서 충분히 빠르고 구조가 단순하므로 이 방법을 선택한다.

## 4. 단계별 알고리즘

1. 현재 최장 답의 시작 위치 `bestStart`와 길이 `bestLength`를 각각 `0`, `1`로 둔다.
2. 각 인덱스 `center`에 대해 `(center, center)`에서 확장하여 홀수 길이 팰린드롬을 찾는다.
3. 같은 인덱스에 대해 `(center, center + 1)`에서 확장하여 짝수 길이 팰린드롬을 찾는다.
4. 좌우 인덱스가 범위 안이고 문자가 같으면 두 인덱스를 바깥쪽으로 한 칸씩 옮긴다.
5. 확장이 끝난 직후의 팰린드롬은 `left + 1`부터 `right - 1`까지이다. 그 길이가 기존 최장 길이보다 클 때만 답을 갱신한다.
6. 모든 중심을 처리한 뒤 기록된 구간을 반환한다.

같은 길이에서는 갱신하지 않기 때문에 더 왼쪽 중심에서 먼저 찾은 답이 유지된다.

## 5. 정확성 증명

### 보조정리 1

`expand(left, right)`는 주어진 중심을 갖는 가장 긴 팰린드롬 구간을 반환한다.

**증명:** 처음 구간은 홀수 중심의 같은 문자 하나이거나 짝수 중심의 인접한 두 위치이다. 반복할 때마다 좌우 문자가 같은 경우에만 두 문자를 함께 포함하므로 확장 중인 구간은 항상 팰린드롬이다. 반복이 끝나는 이유는 경계를 벗어나거나 다음 좌우 문자가 다르기 때문이다. 어느 경우든 같은 중심에서 더 확장한 팰린드롬은 존재할 수 없으므로 반환 구간은 해당 중심의 최장 팰린드롬이다. ∎

### 보조정리 2

알고리즘은 문자열의 모든 팰린드롬이 가질 수 있는 중심을 검사한다.

**증명:** 홀수 길이 팰린드롬의 중심은 어떤 문자 인덱스이고, 짝수 길이 팰린드롬의 중심은 어떤 인접한 두 문자 사이이다. 알고리즘은 각 `center`에서 두 경우를 모두 호출하므로 가능한 모든 중심을 검사한다. ∎

### 정리

알고리즘이 반환하는 문자열은 `s`의 가장 긴 팰린드롬 부분 문자열이다.

**증명:** 보조정리 2에 따라 최적 답의 중심도 검사한다. 보조정리 1에 따라 그 중심을 검사할 때 최적 답 이상의 길이를 갖는 팰린드롬을 얻는다. 알고리즘은 지금까지 찾은 가장 긴 구간만 보존하므로 종료 시 저장된 구간은 전체에서 최대 길이이며, 확장 과정상 팰린드롬이다. 따라서 반환값은 올바른 최장 팰린드롬 부분 문자열이다. ∎

## 6. 시간 복잡도

`n`을 문자열 길이라고 하자. 중심은 `O(n)`개이고 각 중심에서 최악의 경우 `O(n)`칸 확장하므로 시간 복잡도는 `O(n²)`이다. 최종 부분 문자열 생성에는 `O(n)` 시간이 들지만 전체 복잡도를 바꾸지 않는다.

## 7. 공간 복잡도

반환 문자열을 제외한 추가 공간은 인덱스 변수 몇 개뿐이므로 `O(1)`이다. 언어의 문자열 슬라이스가 새 문자열을 복사하는 경우 반환값 저장에는 `O(n)` 공간이 필요하다.

## 8. 엣지 케이스

- 길이 1: 그 문자 자체가 답이다.
- 모든 문자가 같음: 문자열 전체까지 확장된다.
- 팰린드롬 길이가 모두 1: 첫 문자를 유지한다.
- 짝수 길이 팰린드롬: 두 문자 사이 중심을 별도로 검사한다.
- 여러 최장 답: `>`일 때만 갱신하여 먼저 찾은 답을 유지한다.
- 대소문자와 숫자: 문자 동등 비교만 하므로 별도 처리가 필요 없다.
- 빈 문자열: 제약 밖의 입력이지만 방어적으로 빈 문자열을 반환한다.
- 오버플로: 길이가 최대 1000이고 인덱스의 덧셈·뺄셈만 수행하므로 각 언어의 기본 인덱스 정수형에서 안전하다.

## 9. 언어별 구현 차이와 기본 문법 설명

- C++20은 `const std::string&`로 입력 문자열을 빌려 불필요한 복사를 막고, `std::pair<int, int>`로 시작점과 길이를 반환한다.
- C#은 `string`이 불변 참조 형식이므로 그대로 전달하고 `ValueTuple<int, int>`로 두 값을 반환한다.
- Python은 `(int, int)` 튜플과 타입 힌트를 사용한다. 문자열 슬라이스는 결과 문자열을 새로 만든다.
- Rust는 `String`의 UTF-8 바이트를 `&[u8]`로 빌린다. 문제의 문자가 ASCII인 숫자와 영문자로 제한되어 바이트 인덱스가 문자 경계와 일치한다.
- Kotlin은 `Pair<Int, Int>`를 사용하고 `substring`으로 정답 구간을 만든다. `val`은 재할당하지 않는 참조, `var`는 갱신할 수 있는 변수를 뜻한다.
- 다섯 구현 모두 LeetCode용 `Solution.longestPalindrome` 시그니처를 유지하며, 저장소에서 직접 실행할 수 있도록 한 줄 입력을 읽는 로컬 진입점을 함께 포함한다.

## 10. 검증 결과

루트에서 다음 형식으로 실행한다.

```text
printf 'babad\n' | make run problems/longest-palindromic-substring/solution.cpp
printf 'cbbd\n' | make run problems/longest-palindromic-substring/Solution.cs
printf 'a\n' | make run problems/longest-palindromic-substring/solution.py
printf 'aaaa\n' | make run problems/longest-palindromic-substring/solution.rs
printf 'ac\n' | make run problems/longest-palindromic-substring/Solution.kt
```

다섯 언어 모두 실제로 컴파일 또는 실행하여 다음 결과를 확인했다.

- `babad` → `bab` (제공 예제 1)
- `cbbd` → `bb` (제공 예제 2)
- `a` → `a` (최소 길이)
- `aaaa` → `aaaa` (모든 문자가 같음)
- `ac` → `a` (최장 길이가 1이고 답이 여러 개임)
- 문자 `a` 1,000개 → 길이 1,000의 입력 전체 (최대 길이)

C++20, C#/.NET, Python 3, Rust 2021, Kotlin/JVM 구현이 모두 위 테스트를 통과했다.
